## ۴. Claude Code ← MCP با HTTP + Bearer

اتصال از داخل همین ایجنت ممکن بود؛ پس BLOCKED نشد. Claude Code `2.1.296` در حالت headless با transport بومی `http` اجرا شد:

```json
{"mcpServers":{"tududi":{"type":"http","url":"http://localhost:3002/api/mcp","headers":{"Authorization":"Bearer ${TUDUDI_API_TOKEN}"}}}}
```

```bash
TUDUDI_API_TOKEN=$(cat token.secret) claude -p "Call the list_tasks tool from the tududi MCP server (limit 10). Reply with only the task names, one per line." \
  --mcp-config mcp-http.json --strict-mcp-config --allowedTools mcp__tududi__list_tasks --model haiku --output-format stream-json --verbose
```

شاهد (از transcript):
- `init mcp_servers: [{'name': 'tududi', 'status': 'connected'}]`
- `tool_use: mcp__tududi__list_tasks {'limit': 10}` ← `tool_result` بدون خطا، `"count": 5`
- پاسخ نهایی: `Blackout curtains / No screens after 22:30 / Long run 12k / Easy run 5k / Buy running shoes`

تکمیلی: `POST /api/mcp` بدون توکن ← `401`. `/.well-known/oauth-protected-resource` ← `404` (چون OIDC بیرونی خاموش است؛ همان رفتاری که سند در §17.1 گفته بود).

یادداشت: سند `docs/14-mcp-integration.md` فقط پیکربندی `mcp-remote` (stdio bridge) را می‌دهد و پیکربندی مخصوص Claude Code ندارد. پیکربندی بالا قالب بومی خود Claude Code است و اختراعی نیست؛ با آن تست شد.
