## چه ساخته شد

- `backend/modules/ltd-oauth/index.js` (جدید): AS روی issuer = `BASE_URL`، endpointها زیر `/oauth2/*`.
  - DCR (RFC 7591) با **allowlist** برای redirect: `https://claude.ai/api/mcp/auth_callback`، `https://claude.com/…`، loopback با هر پورت برای `localhost` و `127.0.0.1` (Claude Code)، و دو callback ChatGPT.
  - PKCE فقط S256 و اجباری؛ Resource Indicators (RFC 8707) با `aud` = URL دقیق MCP؛ access token از نوع JWT (`typ: at+jwt`، RS256، ۱ ساعت)؛ refresh token چرخشی ۳۰ روزه.
  - Protected Resource Metadata در `/.well-known/oauth-protected-resource` و `/.well-known/oauth-protected-resource/api/mcp`؛ RFC 8414 در `/.well-known/oauth-authorization-server`؛ OIDC Discovery.
  - صفحهٔ consent از session خود tududi استفاده می‌کند. prompt `login` بی‌صدا تمام می‌شود و کاربر فقط یک صفحه می‌بیند که نام میزبان redirect را نشان می‌دهد.
- `backend/middleware/auth.js` (LTD-PATCH، +16): `401` با `WWW-Authenticate: Bearer resource_metadata="…/api/mcp"`؛ پذیرش JWT صادرشده با بررسی `iss`، `aud`، `typ` و `scope ⊇ ltd.read`، **فقط روی `/api/mcp`**.
- `backend/app.js` (LTD-PATCH): mount فقط وقتی `LTD_OAUTH_ENABLED=true` باشد (یافتهٔ پایین).

## یافته‌ها

1. **دو prompt.** `oidc-provider` اول prompt `login` و بعد `consent` می‌خواهد. پاسخ دادن به `login` با grant خالی باعث `op_scopes_missing` و consent دوباره شد. رفع: `login` بی‌صدا از session، و در consent همان چیزی grant شود که `prompt.details` می‌گوید کم است (الگوی مستند oidc-provider).
2. **`offline_access` در درخواست OAuth خالص حذف می‌شود.** `oidc-provider` آن را بدون `openid` نگه نمی‌دارد. برای همین refresh token برای هر client که grant `refresh_token` دارد صادر می‌شود. مستند Claude می‌گوید اگر `offline_access` در `scopes_supported` باشد Claude آن را اضافه می‌کند.
3. **CSP `form-action`.** helmet مقدار `form-action 'self'` می‌گذارد و redirect نهایی پس از POST فرم consent به claude.ai در Chrome مسدود می‌شود. صفحهٔ consent CSP خود را با `form-action 'self' https://claude.ai` می‌فرستد.
4. **بازگشت تست upstream با mount بی‌قید.** افزودن دو Router به `app.js` درخواست را از نگهبان ۱۰۰ لایهٔ همزمان Express 4 رد کرد. Express پس از آن با `setImmediate` ادامه می‌دهد و تست‌هایی که `jest.useFakeTimers()` دارند (`timezone-fixes`) گیر می‌کردند. رفع: mount فقط وقتی فعال است. درس برای فاز ۱ به بعد: هر لایهٔ جدید در `app.js` می‌تواند تست‌های fake-timer upstream را بشکند.

## اتصال claude.ai — چرا انجام نشد

چک‌لیست Claude نیاز به URL عمومی HTTPS دارد و Anthropic باید به آن دسترسی داشته باشد (egress `160.79.104.0/21`). افزودن custom connector هم باید در حساب claude.ai شما انجام شود. باز کردن tunnel عمومی (Cloudflare یا ngrok) روی ماشین شما بدون اجازهٔ صریح انجام نشد.

**کارِ شما برای GREEN** (حدود ۱۵ دقیقه): یک tunnel یا دامنهٔ HTTPS به پورت این spike، اجرای سرور با `BASE_URL=https://<host>` و `LTD_OAUTH_ENABLED=true`، و سپس در claude.ai: Settings ← Connectors ← Add custom connector ← `https://<host>/api/mcp`. آزمون ارزان‌تر و محلی با کلاینت واقعی: `claude mcp add --transport http ltd http://localhost:3014/api/mcp` و سپس `/mcp` ← Authenticate (کلاینت loopback Claude Code).

## به‌روزرسانی فرض‌ها (شاهد مستند، 2026-10-11)

- **A-06 (Developer Mode با پلن کاربر):** ⛔ تأیید نشده. طبق [Help Center OpenAI](https://help.openai.com/en/articles/12584461-developer-mode-and-mcp-apps-in-chatgpt)، MCP کامل (با write) فقط برای Business، Enterprise و Edu است و Pro فقط read/fetch دارد. Plus در مستند رسمی ذکر نشده و گزارش‌های انجمن متناقض‌اند. تا پلن شما معلوم نشود باز است.
- **A-13 (`oidc-provider` بدون CIMD کافی است):** 🟡 از نظر مستند تأیید شد، در عمل آزموده نشد. [مستند Claude](https://claude.com/docs/connectors/building/authentication): «Claude uses a Client ID Metadata Document only when your authorization server metadata advertises both values … and otherwise falls back to DCR». [مستند OpenAI](https://developers.openai.com/apps-sdk/build/auth): «DCR is still supported» و CIMD «preferred» است، نه اجباری. هشدار Claude: با DCR، هر اتصال تازه یک client جدید ثبت می‌کند؛ پس rate-limit و پاک‌سازی clientها لازم است.
