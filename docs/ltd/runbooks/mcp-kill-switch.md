# Kill switch برای MCP

## کِی

یک کلاینت MCP کار عجیبی می‌کند، توکنی لو رفته، یا نمی‌دانی چه چیزی به `/api/mcp` وصل است.

## کجا

تنظیمات ← یکپارچه‌سازی MCP ← **قطع همهٔ دسترسی‌های MCP**، و تأیید. فقط نشست انسان؛ درخواست با توکن `403` می‌گیرد.

## چه می‌شود

| چیز | بعد از kill switch |
| --- | --- |
| grantهای OAuth (claude.ai، ChatGPT، Claude Code) | پاک؛ refresh token کار نمی‌کند، باید دوباره وصل شوند |
| هر توکنی که تا این لحظه صادر شده (`tt_`، access token از OAuth، توکن سرویس ورود OIDC) روی `/api/mcp` | `401` |
| همان توکن‌های `tt_` روی REST API | کار می‌کنند |
| نشست مرورگر | کار می‌کند |
| MCP با stdio | در شروع رد می‌شود |
| توکنی که بعد از این لحظه ساخته شود | کار می‌کند |

MCP حذف سخت ندارد: ابزارهای `delete_*` و `remove_*` نه فهرست می‌شوند نه اجرا. نوشتن‌های Life-to-Day از Journal یا Proposal می‌گذرند و Undo دارند.

## گزینه‌های سبک‌تر

- **فقط خواندن:** کلاینت‌ها می‌خوانند ولی چیزی عوض نمی‌کنند.
- **قطع یک کلاینت:** دکمهٔ قطع کنار همان کلاینت.
- **بعد از rate-limit:** کلاینتی که سه بار در ده دقیقه از ۳۰ نوشتن در دقیقه رد شده، نوشتنش خاموش می‌شود؛ از همین صفحه روشنش کن.

## REST را هم ببند

kill switch عمداً REST را نمی‌خواباند. برای بستن کامل یک توکن، تنظیمات ← کلیدهای API ← revoke. اگر به برنامه دسترسی نداری، برنامه را بایست:

```bash
docker compose -f docker-compose.yml --env-file .env --profile production stop app
```
